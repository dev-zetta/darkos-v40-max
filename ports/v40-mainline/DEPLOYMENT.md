# Integration with an existing ArkOS installation

This port provides source preparation, component patches, runtime text and local staging. It does not flash devices, repartition cards, copy a private root filesystem, or automatically convert upstream build_image.sh into a mainline image builder. Identify the actual board from its DTB wiring and prepare a backup of bootloader prefix, BOOT and ROOTFS plus the games/saves inventory before adapting an image or card. Never reuse a development card's UUID, partition device name, Wi-Fi credentials, SSH identity, ALSA state or complete user settings file.

The tested migration retained the existing bootloader and Debian 13 userspace and always selected mainline, with prior files retained only as backups. A boot.ini must be generated for the target card's actual root UUID, matching Image and DTB paths and a matching initramfs. The tested initramfs uses UUID discovery and switch_root, checks for Btrfs and mounts with rw,noatime,compress=zlib,ssd_spread,noacl,nospace_cache,subvolid=5 so it does not enable newer free-space-tree features on the retained filesystem. Its old development fallback-message text did not implement a fallback; no automatic 4.4 fallback is intended here. The UUID-specific development initramfs and selector are deliberately not published as reusable device binaries.

Stage the newly built kernel/DTB, matching modules and uncompressed native Wi-Fi firmware before changing boot selection. Keep firmware's own licensing/notices. Retain the existing USB installer-disk mode-switch setup and verify the native rtw89_8851bu module resolves after switching. The mainline DTB configures USB host mode; USB gadget/device mode is not ported. Verify AArch32 programs and both private graphics closures because existing emulators use both architectures. Do not assume one successful 64-bit frontend proves every emulator's loader path.

The rendered runtime includes the retained managed frontend unit/runtime directory, serialized power-request helper, pause/finish wrappers, coordinated sleep hooks and separate ALSA-state unit, alongside the mainline-specific overrides. It still depends on the base distribution's audio/input services and sudo policy. Review target service units, sudo rules and launcher environment before applying it to a different image, and enable the reviewed units explicitly rather than copying a development card's entire wants directory. Render both integrity consumers from the newly built frontend SHA-256 together; a stale binary or stale digest can prevent launch. Keep the full frontend resources tree beside the executable. The private environment must be inherited by emulators so they do not fall back to vendor Mali on mainline. Install only reviewed paths and leave network profiles, host keys, fstab, games, BIOS, saves, calibration and unrelated user preferences intact.

Set only AudioDevice to Playback in the frontend settings, retaining its rootless XML format and other settings. Master is capture-only on this codec. Set only BatteryPlus Config mode to pmic, retaining calibration; its service HOME/XDG configuration directory must point to the intended user. Mainline RK817 has capacity and voltage_avg, while the old voltage_now-only reader failed. The board-specific ALSA helper restores user volume into its separate state, selects the physically working HP DAC path and uses native alsactl locking. Do not import a test card's volume or saved mixer state.

For existing PSP settings, exit PPSSPP and run a plan before an explicit apply with a fresh backup directory. Both .ini and .ini.sdl matter because the distribution launcher copies the saved launch configuration over the active one. Per-game control overrides need the additive FN binding too; explicit per-game graphics choices are retained. Example paths below belong to the standard layout, not an automatically detected target:

```sh
python3 scripts/configure_ppsspp.py --database /opt/ppsspp/assets/gamecontrollerdb.txt --system-dir /roms/psp/ppsspp/PSP/SYSTEM
sudo python3 scripts/configure_ppsspp.py --database /opt/ppsspp/assets/gamecontrollerdb.txt --system-dir /roms/psp/ppsspp/PSP/SYSTEM --apply --backup-dir /var/backups/v40-psp-before-fix
```

Before changing boot.ini last, verify file checksums, permissions, matching module symbol CRCs, service syntax, resource closure and protected game/save inventories. Sync, unmount and verify filesystems with the actual card mapping. The working boot path was full shutdown followed by power-on; software-reboot display reliability and suspend/headphone transitions need separate testing. A new public image must complete those checks and broader emulator/audio validation before being advertised as a finished release.
