The subsequent [shutdown near reported 19 percent](BATTERY_SHUTDOWN_20261116.md) remains unresolved. Charging detection and visible percentages are accepted reporting fixes, not full-cycle calibration or proof of a correct shutdown estimate.

The user later photographed the actual pack label: 3.7 V, 4000 mAh, 14.8 Wh. The 3380 mAh design value below was inherited from the shipped device tree and does not match that nominal label. The current retained FCC is still 3000 mAh after battery reconnection; the label alone does not measure usable capacity or justify overwriting the retained counter/FCC. No voltage, OCV, current or protection threshold was changed to match the label's Wh figure.

The reported twenty-point same-boot jump was not reproduced; one capture cannot establish accurate calibration or exclude an intermittent defect.

A separate charger-reporting defect was confirmed: positive charging current coexisted with ONLINE=0 and Not charging. The factory tree supplies GPIO0_B3 as an active-high DC detector; the old driver treats it independently of PMIC USB plug detection. Read-only hardware snapshots showed that input high with the adapter connected and low while held disconnected, while the PMIC USB detector and its plug IRQ counters stayed unchanged. It was unclaimed and already configured as input. The candidate's pull-none/bias-disable pin configuration matches the factory pinctrl entry exactly; USB voltage was unsuitable as a substitute because OTG already supplied approximately 5 V before charging.

The local optional dc-detect-gpios driver support acquires the charger child's firmware-node GPIO as input and samples it through the existing eight-second monitor. It adds no IRQ/workqueue, GPIO output, boost control, charge-current/voltage setting or manual calibration write. Supply ONLINE reports USB or DC presence. Positive current with DC present reports Charging; negative current remains Discharging and zero current does not imply Full. Read errors retain the previous DC state and produce a rate-limited warning. Other boards without the property retain the existing path. The input is reporting support, not proof that every board's external charger is electrically equivalent to RK817's internal charger.

Newer mainline source still contained gauge defects addressed by [ROCKNIX PR3305](https://github.com/ROCKNIX/distribution/pull/3305). The focused backport preserves Chris Morgan and Jacob Cook's authored NVRAM-scale and counter-first boot/rested-OCV corrections. Saved state uses a 0..100000 scale, not the old 10000 ceiling; established batteries no longer choose a charger-biased PWRON voltage solely because OFF_CNT reaches its threshold. A valid rested OCV pair can correct a counter differing by more than the donor's five-point threshold. A separate local guard prevents multiplication overflow when validating corrupt learned full-capacity data. The observed 3000 mAh value did not trigger that overflow. The build excludes the separate constant-current sleep estimate, terminal-voltage boot-bound policy and off-state power-bit changes. These fixes address identifiable driver defects without proving the user's exact symptom or an audio repair.
