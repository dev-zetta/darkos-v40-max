## Actual boot path

On the captured baseline boot, firstboot.service was masked and did not run; clone.service was absent. clone.sh's BSP Playback Path→SPK branch was not the active boot mechanism, and current mainline instead exposes Playback Mux. That saved mainline mixer state contained HP and Playback181/255, approximately−32.36dB. The legacy SPK_HP state was bypassed. No startup writer setting the RK817 Playback control to100percent was found.

On that baseline boot, the two same-policy restore helpers finished at12.278 and12.307seconds, followed by the initial-state check at12.902seconds and frontend launch at12.925seconds. First I2S playback started around21.929seconds. The frontend reads existing volume and opens its audio device even with background music disabled. Thus the user's menu-entry timing points toward first PCM/DAPM power-up rather than a first-boot SPK route switch; it is not electrical proof of the transient's source. Duplicate restore helpers can be simplified separately, but both select HP and use ALSA file locking, and their overlap is not a demonstrated cause.

## Emulator-side limits

Saved PPSSPP settings select granular synchronization and FillAudioGaps=False; the launch override only selects1024-frame audio buffers. In the installed [granular mixer](https://github.com/hrydgard/ppsspp/blob/fa50bb1976065c4f8b1b47af227d367fe9771555/Core/HW/GranularMixer.cpp), an empty queue can output zero granules without incrementing the underrun counter under that option, and an overfull queue deliberately jumps its read position. Neither ALSA XRUN0 nor an internal counter alone establishes clean output. Existing PPSSPP file logging is disabled. The binary is stripped, so named internal queue counters cannot be read reliably without guessing addresses.

The [PSP channel producer](https://github.com/hrydgard/ppsspp/blob/fa50bb1976065c4f8b1b47af227d367fe9771555/Core/HLE/__sceAudio.cpp) also has a partial-fill path that can retain the old tail of a64-frame mix buffer; no active occurrence was observed. SDL callback locking/partial-write handling showed no demonstrated concurrent overwrite. Current RW_INTERLEAVED playback cannot be mapped with the earlier MMAP menu-capture method, and kernel tracing hooks are disabled. A future instrumented build should expose queue occupancy, zero-fill events, playhead jumps and callback duration, with aligned digital taps where justified. New upstream PPSSPP buffering/pacing work is relevant research, not a verified hardware repair.

## Optional mute-ownership diagnostic

A source-ordering concern exists in the retained baseline codec: the inverted DAC Mute Off supply clears active-high DACMT at0x38bit0 before later HP/PLL supplies and DAC widgets finish powering up. The normal ASoC prepare path also unmutes after DAPM power-up, making the earlier writer redundant. The existing volume ceiling is already−6.75dB and probe initialization is quiet; copying the issue's5.10 gain/OCP constants is not the missing change.

The separate [optional patch](../diagnostics/optional/0001-rk817-v40-dacmt-ownership.patch) is default-off and limited to the private V40 board compatible. Boot opt-in is snd_soc_rk817.v40_dacmt_guard=1. It checks reset and asserts DACMT before initialization, gives this device a private widget table, prevents that widget from unmuting during power-up, and retains an assert-only PRE_PMD mute event for DAPM-only shutdown. Existing DAI preparation remains the only unmute owner. Gains, PLL/format configuration, HP/Class-D routing, DMA implementation and trigger timing are unchanged.

The PRE_PMD event sorts earlier within the supply class but still after DAC/output power-down classes. This is not a full analog ordering repair. Digital mute cannot guarantee suppression of analog bias, reset or amplifier-power transients. Direct pin power-down/re-enable while a stream remains prepared can stay muted until a later DAI prepare/unmute; headphone transitions and suspend/resume remain hardware-unverified. The callback uses sleepable DAPM context; no I2C work is moved into an atomic trigger.

The final source passes24 static checks and16 actual-function host cases under UBSan, plus independent review. The first source candidate was superseded before activation because it omitted DAPM-only shutdown muting. Kernel build, ABI checks, installation readback and audible boot acceptance are separate validation levels. The optional patch remains outside the default recipe and is not an accepted boot-pop or scrambling repair.
