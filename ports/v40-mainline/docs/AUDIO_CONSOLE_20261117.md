# Channel isolation and standalone audio test, 2026-11-17

The user asked whether the single speaker receives mono audio and requested channel isolation, then a standalone console program with EmulationStation fully stopped. Fresh live readback shows stereo S16_LE at 44,100 Hz with both HP DACs active. Codec register `0x38=0x20` selects L/R mode with its digital mixer disabled. The physical external amplifier's input network remains untraced, so the number of speakers does not establish where or how the two channels combine.

The board's custom Playback control reads the left DAC attenuation and writes the same value to both DACs. Giving that control unequal left/right values would therefore not be a valid channel-isolation test. The reference instead supplies zero samples to the unselected channel and preserves the hardware gain and HP route.

## Root cause of the slow frame clock, 2026-11-18

The PX30 technical manual limits the I2S1 fractional divider input to 600 MHz. The retained shipping kernel enforces that limit. The mainline driver selected a 1.2 GHz GPLL with a divide-by-one prescaler and a fraction of 147/15625, feeding the fractional divider at twice its specified maximum. The register math still produces a nominal 11.2896 MHz master clock and 44.1 kHz frame clock. The documented input limit means that this arithmetic does not predict the physical clock reliably in the original configuration. [Rockchip PX30 Technical Reference Manual, §2.8.3, Table 2-1](https://opensource.rock-chips.com/images/8/84/Rockchip_PX30_TRM_V1.1_Part1-20180917.pdf) · [Upstream clock-limit proposal](https://lists.infradead.org/pipermail/linux-arm-kernel/2020-October/612520.html)

Three standalone trials used the same 529,200 zero frames and negotiated stereo S16_LE PCM geometry with the menu fully stopped. A temporary module built against the running kernel held only the I2S1 prescaler at 600 MHz and adjusted the fraction to 294/15625. GPLL stayed at 1.2 GHz and the intended MCLK and LRCK stayed at 11.2896 MHz and 44.1 kHz. The CLKSEL register pair was `0x0400 / 0x00933d09` in both original trials and `0x0401 / 0x01263d09` in the compliant trial. The I2S format and clock divider stayed at TXCR `0x000f` and CKR `0x00033f3f`. The module changed the local clocks with the PCM closed and RK817 DAC mute asserted.

The same CPU frequency of 1.296 GHz, GPU operating point of 200 MHz and reported 0.950 V logic rail applied in all three trials. LRCK edge counts use windows with at least 94 percent sampling coverage and exclude read gaps longer than 7 microseconds. The corrected GPIO estimate is approximate. The 600 MHz run also transferred all frames in 12.018 seconds, independently supporting a near-nominal frame rate. PC receive intervals agreed with the handheld durations within 0.6 percent. Temperature decreased across the first, second and third trials, while correct timing appeared only during the middle trial.

A second comparison retained the exact same open menu PCM and I2S divider words. A temporary devfreq request brought the GPU from 480 MHz and a reported 1.125 V logic rail down to its supported 200 MHz and 0.950 V operating point. The median frame clock changed from 44.15 to 29.21 kHz. It returned to 44.17 kHz when the request was removed. A brief process pause that left PCM open showed 44.10 kHz at 300 MHz and 0.975 V. The low operating point thus exposes the faulty 1.2 GHz input even with EmulationStation and its original PCM present. The 600 MHz test demonstrates that the audio clock can operate normally at 0.950 V. GPU frequency and logic voltage moved together, so the measurements establish operating-point dependence. They leave the electrical contribution of voltage alone and the exact rate inside the out-of-spec divider unresolved.

A lasting correction should constrain the PX30 I2S1 fractional input and retain the full set of board operating points. The original clock settings, PCM owner, speaker gain and routing, and devfreq policy were verified after the two temporary modules were removed. The kernel retains the out-of-tree module taint flag for this boot. The compliant clock comparison used digital silence. Speaker pitch, noise, stereo behavior, cold boot, and 44.1/48/96 kHz transitions remain to be verified with a production correction. Full captures and checksums are under `evidence/mainline-clock-cause-2026-11-18/`.


## I2S1 clock correction and cold-boot follow-up, 2026-11-18

The first implementation ran the 600 MHz adjustment during PX30 clock-controller initialization. The handheld showed its first logo, then the image scrambled and normal boot did not complete. The card held the exact selected image, matching kernel header, device tree and initramfs. Its last journal and boot snapshot belong to the previous boot, and its crash archive has no new entry. The failed image, selector and manifest are preserved under `evidence/mainline-i2s-retry-2026-11-18/failed-early-cru/`.

The failed build could change the fractional child rate before the CRU protected its critical clock branches. The fractional divider uses `CLK_SET_RATE_UNGATE`, so a rate change can temporarily enable its parent chain and later disable a PLL whose firmware use has no framework enable reference yet. GPLL feeds the PMU bus and is a possible parent for VOP bus clocks. The code establishes this risk. The failed boot did not capture the actual clock transition.

The revised default patch applies the same 600 MHz limit from the V40 I2S1 platform probe after critical clock protection and before ASoC card registration and MCLK programming. It uses a private clock handle and releases that handle on probe failure or unbind. The driver checks the PX30 board and exact I2S1 clock names. ASoC still selects the fractional output for each stream rate.

Fresh source preparation from the pinned Linux 7.3.4 archive verified the revised patch. The exact-device rebuild used the previous working 7.3.4-v40.1 build and preserved the configuration, optional PL330 code and DAC mute guard. Its PX30 CRU object and ARM64 Image header are byte-identical to the working build. Build ID is `9b9fa24e4d8ee542980a34654afa47e9bde5bbd9` and Image SHA-256 is `5637d0bc66d6fadc50bd601c93c979b8e3d5bd700dc3fb3e4f86c72f53f4a5a7`. All 17,383 export CRCs are byte-identical. All 871 retained and 871 rebuilt modules passed 34,885 import CRC checks per set.

The revised image, selector, prior image, device tree and initramfs were verified from the SD card after a read-only remount. For offline rollback, copy `mainline/i2s-probe-clock-20261118/baseline-boot.ini` to `boot.ini` at the root of BOOT. The replacement is selected for its first cold boot. Physical menu, clock rate, and playback acceptance are pending.
