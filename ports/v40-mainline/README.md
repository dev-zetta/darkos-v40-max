# V40 Max / R36S Plus mainline development port

This port runs Linux **7.3.4-v40.1**. It targets the RK3326/Cortex-A35, 720×720 stock wiring identified by factory DTB SHA-256 `06b611d370f32165d340fb8184f54cc2f735fb312ed7b7a8e59e4cb028e3d05f`. Check the board wiring and panel before using it on a device with a similar name.

The user confirmed working menu/display/controls, speaker music after clean shutdown and power-on, RTL8851BU USB Wi-Fi/SSH, and the final PSP image and FN/SELECT/START corrections. The I²S1 fractional clock correction resolved the tested PPSSPP scrambling. Existing games, saves and unrelated settings were retained during migration. Read the [kernel update instructions](KERNEL_RELEASE.md), [validation and limitations](docs/VALIDATION.md), [build instructions](BUILD.md), [deployment requirements](DEPLOYMENT.md), and [source provenance and credits](UPSTREAM.md).

The default kernel patch set contains the board, panel/DSI initialization, gamepad API port and board-scoped codec/mixer compatibility. Native rtw89 supports the tested AX900 dongle, whose installer-disk and Wi-Fi USB IDs are `0bda:1a2b` and `0bda:b851`. Retain the distribution's USB mode-switch setup and stage the native driver's uncompressed firmware. Private ARM64/ARM32 Mesa with GLES1 and a Mesa-compatible SDL keep preserved vendor/global graphics libraries separate from the mainline runtime.

The complete CRC-specific SDL gamepad entry restores normalized SELECT/START/FN events. The additive PPSSPP helper disables SkipBufferEffects in the general and saved launch configurations and adds FN to Pause, including existing per-game control overrides. It preserves original button alternatives, preferences, volume and saves; it defaults to a plan and requires a new backup directory for writes. Existing per-game graphics choices are retained and may still override global rendering settings.

The current frontend detects native RK817 batteries by their power-supply type, reads battery voltage_avg when voltage_now is unavailable, and keeps Wi-Fi/Bluetooth/battery status within the screen while preserving explicit theme geometry. A live 720x720 framebuffer shows the battery icon and percentage beside both radio icons. The kernel source carries focused gauge corrections and reporting for the factory DC-detect input; charging-cycle accuracy and the separate idle audio noise remain under investigation. Read the [battery/status follow-up](docs/BATTERY_STATUS_20261116.md) before treating a displayed percentage as calibrated capacity.

The [controlled idle-noise investigation](docs/AUDIO_ANALOG_20261116.md) retains separate static and repeating-crack symptoms. Digital mute and verified codec output power-down did not suppress the reported noise; physical USB Wi-Fi adapter removal stopped the cracks while lower static remained, and reconnection returned the cracks. This is diagnostic evidence for a dongle-dependent contribution, not a completed audio fix or proof of RF interference. All temporary audio controls were restored.

USB-C earbuds reproduced noise while the later audible Bluetooth reference had clean gaps. Different power and hub conditions limit attribution; a shared power/electrical path remains a hypothesis. The [shutdown near reported 19 percent](docs/BATTERY_SHUTDOWN_20261116.md) also remains unresolved, with no verified 20-percent shutdown rule, new capacity calibration or protection change.

Physical inspection now confirms the RK817-1 codec and a separate TCS7191CB analog speaker amplifier. Its control/supply wiring remains untraced; the initially proposed NS-family identification was rejected. The battery label is 4000 mAh, whereas the inherited design parameter is 3380 mAh and retained FCC is 3000 mAh. These findings and the unresolved noise after battery disconnection are recorded in the investigation; no speculative amplifier GPIO or capacity reset was installed.

The PL330 continuous-DMA experiment is optional and default off. The released kernel uses standard PL330 DMA in its tested configuration. The experimental frontend V4 was subsequently activated without an accepted audible improvement. The experimental perfmax change was activated, encountered two reported system freezes on PSP launch, and was rolled back. The previous helper launches the game successfully and also reaches 480 MHz through simple_ondemand. See the [audio follow-up](docs/AUDIO_INVESTIGATION_20261115.md) for the earlier PSP slowdown and idle output-noise findings.

The [full image guide](IMAGE.md) covers building and testing a fresh SD card. The [kernel update](KERNEL_RELEASE.md) targets a compatible existing V40 mainline installation.
