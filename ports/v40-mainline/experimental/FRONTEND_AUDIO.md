# Audio callback candidate

This branch moves playlist scanning, song loading/freeing and application-state updates out of SDL_mixer's music-finished callback. The callback only sets an atomic notification; AudioManager::update consumes it on the UI thread. Removing the hook precedes cancelling the notification so an in-flight callback cannot reassert a stale request after stopMusic.

The complete production AudioManager source passed eight behavioral fixture cases. The accepted V3 source is a negative control for callback-thread work, and a mutation reversing hook removal and flag clearing fails cancellation coverage. An AArch64 build completed with unchanged dynamic-library dependencies; its callback contains no function calls. This is bounded software evidence, not proof of physical audio quality.

The built V4 candidate SHA-256 is 39339a1e77bcc7582958a807751a62de2e79bcac91a0918a0094c79c1feb48ac. It was activated with both integrity consumers updated, and the menu returned successfully. The user reported menu audio unchanged or worse; the bounded timed capture contained no navigation key events and is not a matched navigation comparison. The current V6 frontend retains this correction and adds native battery/status and START-menu footer fixes, with binary SHA-256 6da989f88ad8431472f12290a58146c0ff916ce2a0e6e794596d31400175e82b and source commit 6f78f3cf9a9df5956a1eac43ea0d6b2703a74f3b. The default twelve-patch source series now includes the callback change; this standalone artifact remains for provenance and must not be reapplied. Background music remains disabled at the user's request. This track-transition correction does not establish a fix for navigation clicks, preview mixing or PSP audio scrambling.
